PURPOSE OF THIS README
----------------------
This file is the main guide for the project. It explains:

======================================================================
1. PROJECT FILES
======================================================================

index.html
    Main web page structure.
    Contains navigation, forms, tables and application sections.
    Does NOT contain the player dataset.

css/style.css
    All page styling and responsive design.
    Contains both visual themes:
      - Court Light
      - Sunrise Rally

js/app.js
    Main JavaScript logic.
    Loads XML, parses XML, performs XML DOM CRUD, refreshes the page,
    serializes XML, downloads/imports XML and exports Excel.

xml/pickleball.xml
    PRIMARY project dataset.
    Contains tournament information, clubs, 24 players and 12 matches.

images/pickleball-logo.svg
    Small optimized vector logo used by the website.

README.txt
    This guide.

2. HOW TO RUN THE PROJECT
======================================================================

IMPORTANT:
Do NOT double-click index.html and run with file:// because fetch()
may be blocked by the browser.

OPTION A - GITHUB PAGES (recommended for submission)
----------------------------------------------------
1. Create a PUBLIC GitHub repository.
2. Upload the CONTENTS of this project folder to the repository root.
3. Check that index.html is directly at the root of the repository.
4. Go to:
      Settings > Pages
5. Set:
      Source: Deploy from a branch
      Branch: main
      Folder: /(root)
6. Save.
7. Wait until the GitHub Pages Action finishes.
8. Your URL will normally look like:
      https://YOUR-USERNAME.github.io/YOUR-REPOSITORY/


OPTION B - XAMPP
----------------
1. Copy the project folder into XAMPP htdocs.
2. Start Apache.
3. Example URL:
      http://localhost/TMS6124_Pickleball_Project_CodeOnly/


OPTION C - VS CODE LIVE SERVER
------------------------------
1. Open the project folder in VS Code.
2. Install Live Server extension if needed.
3. Right-click index.html > Open with Live Server.


======================================================================
3. WHAT EACH APPLICATION PAGE DOES
======================================================================

A. DASHBOARD
------------
Purpose:
- Shows tournament information from XML.
- Counts players, clubs, matches and confirmed registrations.
- Groups player records by Club and Category.

Lecturer explanation:
"The dashboard does not use hard-coded numbers. app.js reads the
current XML DOM and recalculates the values after CRUD operations."


B. PLAYERS
----------
Purpose:
- Main XML DOM CRUD page.
- Search/filter players.
- Add, edit and delete player records.
- Includes the required Confirmed Player by Category filter.

CREATE:
- Press + Add Player.
- Fill in the form.
- Press Save Player.
- JavaScript creates a real <Player> XML node and appends it to <Players>.

READ:
- The player table is generated by reading <Player> nodes from xmlDoc.
- Search, Category and Status controls filter the XML DOM display.

UPDATE:
- Press Edit beside one player.
- The form is filled from that XML node.
- Press Save Player.
- JavaScript updates the child elements in that XML node.

DELETE:
- Press Delete.
- A confirmation message is shown.
- JavaScript removes the actual <Player> XML node using removeChild().


C. SCHEDULE
-----------
Purpose:
- Shows all match/court schedule data from <Matches> in the XML DOM.
- Demonstrates that the XML model supports tournament operations beyond players.


D. PUBLIC RESULTS
-----------------
Purpose:
- Shows only matches where <Status>Completed</Status>.
- Displays winner information for spectators/participants.


E. DATA TOOLS
-------------
Purpose:
- Demonstrates XMLSerializer and persistence/save.

Buttons:
1. Download Updated XML
   - Serializes current xmlDoc.
   - Downloads pickleball_updated.xml.
   - This is the main required persistence evidence.

2. Import Saved XML
   - Select a previously downloaded XML file.
   - Parses the file into xmlDoc again.
   - Demonstrates saved changes can be reloaded.

3. Export Data to Excel
   - Extra feature.
   - Creates Tournament Info, Players and Matches worksheets.
   - Reads the CURRENT XML DOM, so CRUD changes are included.
   - Uses SheetJS CDN.
   - If the library cannot load, it falls back to CSV player export.

4. Reset to Original XML
   - Clears browser autosave.
   - Restores the original pickleball.xml loaded from the server.

5. XMLSerializer Preview
   - Shows the current XML DOM as serialized text.

4. SIMPLE PROJECT WORKFLOW TO EXPLAIN TO THE LECTURER
======================================================================

You can explain the project in this order:

1. "pickleball.xml is my main structured dataset."

2. "In app.js, fetch() loads pickleball.xml from the web server."

3. "DOMParser converts the XML text into xmlDoc, which is an XML DOM tree."

4. "The web interface reads data from xmlDoc and displays it."

5. "CREATE, UPDATE and DELETE change XML nodes inside xmlDoc directly."

6. "After each CRUD action, the interface is refreshed from the current XML DOM."

7. "XMLSerializer converts the modified DOM back into XML text."

8. "Download Updated XML preserves the changes outside browser memory."

9. "The saved XML can be imported again to prove the changes are preserved."

5. IMPORTANT FUNCTIONS IN js/app.js
======================================================================

loadXmlData()
    Downloads and parses the XML file.

parseXmlText()
    Uses DOMParser and checks that XML is well-formed.

refreshAllViews()
    Refreshes all application displays from xmlDoc.

renderPlayers()
    READ operation / player listing.

renderConfirmedCategoryPlayers()
    Required category filter showing only Confirmed players.

createPlayerFromForm()
    CREATE operation.

createPlayerNode()
    Builds a new <Player> XML element.

updatePlayerFromForm()
    UPDATE operation.

findPlayerById()
    Finds the XML node with a specific PlayerID.

deletePlayer()
    DELETE operation.

serializeXml()
    Uses XMLSerializer to convert xmlDoc back into XML text.

downloadUpdatedXml()
    Downloads the current XML as pickleball_updated.xml.

importSavedXml()
    Loads a previously exported XML file.

exportToExcel()
    Extra function that exports current XML data to an Excel workbook.

6. WHERE TO CHANGE COMMON THINGS
======================================================================

CHANGE TOURNAMENT NAME / DATE / VENUE
    File: xml/pickleball.xml
    Section: <Tournament>

ADD / EDIT STARTING PLAYER DATA
    File: xml/pickleball.xml
    Section: <Players>

ADD / EDIT MATCHES
    File: xml/pickleball.xml
    Section: <Matches>

CHANGE WEBSITE TITLE / MENU WORDING
    File: index.html

CHANGE COLOURS
    File: css/style.css
    Section: :root

CHANGE SECOND THEME COLOURS
    File: css/style.css
    Section: body[data-theme="sunrise"]

CHANGE RESPONSIVE/MOBILE DESIGN
    File: css/style.css
    Section: @media rules at the bottom

CHANGE XML FILE LOCATION
    File: js/app.js
    Line near the top:
      const XML_FILE = "xml/pickleball.xml";

7. IF THE LECTURER ASKS: "ADD ANOTHER PLAYER FIELD"
======================================================================

Example: add Email.

You need to update these locations:

1. xml/pickleball.xml
   Add:
      <Email>example@email.com</Email>
   inside every <Player> record if required.

2. index.html
   Add an Email input to the Add/Edit Player form.
   Add an Email table column if you want it displayed.

3. js/app.js
   createPlayerNode()
      Add createTextElement("Email", ...)

   openEditPlayerForm()
      Load Email into the form.

   updatePlayerFromForm()
      Call setChildText(player, "Email", ...)

   renderPlayers()
      Read/display the Email field.

   exportToExcel()
      Add Email to the Excel headings/rows if required.

This is why the project keeps each major function clearly separated.

9. IMPORTANT NOTES
======================================================================

- XML DOM is the primary data-manipulation mechanism.
- localStorage is only a browser convenience.
- Download Updated XML is the main persistence method for GitHub Pages.
- GitHub Pages cannot directly overwrite the repository XML file from browser JavaScript.
- Excel export is an extra reporting feature, not the XML persistence method.
- Keep the website online during the marking period.
- Both project members should be able to explain fetch(), DOMParser,
  XML DOM CRUD, XMLSerializer and the save/export workflow.
